## 执行

在 `D:\大三\数据库\pj1_2` 使用已安装锁定依赖、Node22及项目专属27019/rs0运行：

```powershell
npm run test:phase2:acceptance
```

该入口串行运行34组，避免固定测试端口碰撞。默认 `npm test` 仍只是原集成测试，不能替代该完整验收入口。需要定向重跑时：

```powershell
node scripts/run-phase2-acceptance.mjs --only=acceptancejourney,acceptancepermissions,acceptancescale
```

每轮创建新的 `docs/testing/phase2-runs/acceptance-<时间>-<随机号>/`，包含机器汇总、子命令的原输出/退出码、应用库前后指纹、源码摘要、监听PID与临时端口释放记录。失败运行和后续重跑分目录保留；失败不能覆盖为PASS。缺少环境或构建失败会如实阻断，不跳过后宣称全部通过。

## 范围限制

- 所有业务夹具使用新唯一 `project2_test_*`；迁移组仅使用受控合成备份与对应恢复库。两个应用库只读前后指纹，不清库、不降验证器、不写样例。
- 用户3200/5200服务和27019实例保持运行。专门的应用启动脚本要求端口空闲，完整回归不重启用户服务，改以独立浏览器服务器、入口隔离与监听归属核验覆盖本轮相关检查。
- 已有故障钩子和真实事务交错不能声称完成真实断网、宕机或主节点切换。
- 真实P1业务数据迁移、数据库角色认证强制部署及最终课程报告不在本轮自动验收内；人工验收在用户实际操作前保持“未执行”。
