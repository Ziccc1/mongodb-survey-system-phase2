## 功能范围更新

问卷定义编辑保存、不可变发布快照、历史读取和分版本统计列入第一阶段必做；“已有答卷后永久锁定”和“必须复制才能修改”已被替换。复制问卷为可选增强。填写草稿、自动保存、断点恢复仍为可选；跨版本合并、去重人数、策略修改、改写已提交答卷暂不实现。

## 工程验收建议

以下是为完成作业而提出的实现和验证建议，并非原文逐字要求。

- 密码使用安全哈希保存，不保存明文。
- 后端检查问卷状态、权限、答案类型、约束和实际答题路径；不能只依靠网页校验。
- 题目与选项采用稳定 ID；显示顺序不作为永久引用。
- 发布前检查规则是否引用存在的题目、选项，是否出现不可支持的循环或矛盾约束。
- 统计使用选定发布版的有效提交和该版定义；未回答和被跳过的数字题不按 0 计算；累计只是份数总计，不代表跨版题目合并。
- MongoDB 设计说明应解释嵌入与引用、索引、冗余取舍、文档增长与未来修改，而不只是罗列字段。
- 如需限制重复提交，须在数据库或原子写入层面处理并发；不能只在写入前查询一次。

## 测试记录格式

每个测试编号都应补全：关联需求、前置条件、操作步骤、输入、预期输出、实际输出、通过或失败、执行人、执行日期、证据文件。当前 T01—T21 与新增 T22—T35 均是待执行业务测试项，不代表已经完成。历史 12 项旧 Schema 检查保持原记录，不能替代新版验证。

优先增加的边界场景：跨用户访问、选项 ID 伪造、多选重复选项、长度上下界、数字 0 与小数、跳过必答题、改答后的路径变化、无效跳转、截止瞬间、同时重复提交、无答卷统计。
